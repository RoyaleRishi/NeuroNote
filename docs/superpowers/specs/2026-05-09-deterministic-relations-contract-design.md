# Deterministic Relations: Contract & Purge Design

**Status:** approved, ready for implementation plan
**Date:** 2026-05-09
**Author:** rishis (with Claude)

## Problem

Since the deterministic-extraction refactor (commit `e03996c`), the structural-relations
pipeline (`api/src/app/nlp/structure_relations.py`) has been emitting **zero edges per
note save**. The bug is a single attribute-name mismatch — the algorithm reads
`attrs.id`, but the frontend's TipTap editor and the storage-layer block stamper
(`BlockRepository._ensure_block_uid`) write `attrs.blockUid`. Every block walk
short-circuits at `if not block_id: continue` because the gate condition is
unreachable on real data.

A user-visible symptom is that `extraction_summary.relation_count == 0` on most
notes. The graph view still has 142 SUBTOPIC_OF and 89 SYNONYM_OF edges — but
those are **durable concept-meta edges left over from the pre-refactor LLM
pipeline**. They are not being regenerated by the deterministic code; they are
just persistent enough to survive per-note delete-and-replace sync.

A second observation surfaced during investigation: the structure-relations
module also performs concept matching by case-insensitive substring
(`c.lower() in text.lower()`), which silently produces false positives ("AI" in
"again", "JS" in "adjustments").

This design fixes the contract drift, removes the unreliable substring matcher,
collapses three local tree walkers into one shared utility, deletes legacy
LLM-era edges from the graph, and pins the contract with explicit Pydantic + TS
types so the next regression of this shape fails loudly at import time.

## Non-goals

- Block-ID stamping at every persistence boundary. `BlockRepository.replace_blocks`
  is the only producer of `notes.content_json` today; adding stampers at routes
  or imports defends against a hypothetical second producer.
- A full Pydantic schema for the recursive TipTap document. The contract is
  pinned only at the block-attrs level — the part this codebase actually
  consumes.
- A new dashboard or alert pipeline for the health metric. A single log line is
  the signal.

## Architecture

```
                       ┌──────────────────────────────┐
  Frontend TipTap ─────┤                              │
                       │                              │
  Markdown import ─────┤  ensure_block_uids(doc)      ├──── notes.content_json
                       │  (one helper, one entry)     │     (every structural
  Future producers ────┤                              │     block has blockUid)
                       └──────────────────────────────┘
                                       │
                                       ▼
                          NoteNlpPipeline.derive_relations
                          - reads attrs.blockUid only
                          - drops the missing-ID gate
                          - word-boundary concept matching
                          - single tree walk
```

The contract is enforced at the storage boundary by `BlockRepository.replace_blocks`,
which calls `ensure_block_uids` before persisting `content_json`. The NLP
pipeline reads from `notes.content_json` after this stamping has run, so it can
treat `attrs.blockUid` as a guaranteed-present field.

The full document tree remains `dict[str, object]` in route models. Pydantic
validation is applied only to block attrs — the only place this codebase
actually depends on a fixed schema.

## Components

### New: `app/utils/tiptap.py`

Three pure helpers, no DB:

- `ensure_block_uids(doc: dict) -> dict` — idempotent. Adds `attrs.blockUid` to
  every structural block missing one, regenerates colliding UIDs. Logic
  promoted verbatim from the existing `_ensure_block_uid` /
  `_extract_blocks` in `block_repository.py`.
- `walk_structural_blocks(doc: dict) -> Iterator[BlockInfo]` — single tree walk
  yielding `BlockInfo(block_uid, kind, text, parent_uid, depth)`. Replaces the
  three separate walkers (`_walk_blocks`, `_list_item_groups`,
  `_bold_prefix_concepts`) currently in `structure_relations.py`.
- `find_concept_mentions(text: str, concepts: list[str]) -> set[str]` —
  word-boundary regex match (`\b<concept>\b`, case-insensitive). Replaces every
  `c.lower() in text.lower()` substring check.

Plus a shared `_extract_plain_text` (currently private in `block_repository.py`)
moves here and is imported from both call sites.

### New: `shared/contracts/python/v1/document.py` + `shared/contracts/ts/v1/document.ts`

```python
class TipTapBlockAttrs(BaseModel):
    blockUid: str                      # required on every structural block
    parentBlockUid: str | None = None
    indentLevel: int | None = None
    level: int | None = None           # heading-only

STRUCTURAL_BLOCK_TYPES: frozenset[str] = frozenset({
    "paragraph", "heading", "blockquote", "codeBlock",
    "bulletList", "orderedList", "listItem",
    "taskList", "taskItem", "mathBlock", "image",
})
```

The TS interface mirrors `TipTapBlockAttrs`. Existing route models continue to
type `content_json` as `dict` — the contract pins block-attrs only.

### Modified: `api/src/app/nlp/structure_relations.py`

Rewritten around `walk_structural_blocks` + `find_concept_mentions`:

- Reads `attrs.blockUid` only — no `attrs.id` fallback.
- The `if not block_id: continue` gates are deleted. The contract guarantees
  `blockUid` is present after `ensure_block_uids` has run; this code is the
  consumer of that contract.
- Single tree walk; the five relation accumulators
  (MENTIONED_TOGETHER, SUBTOPIC_OF, SIBLING_OF, REFERENCES, DEFINED_BY) all
  observe one pass.
- All concept matching is word-boundary regex.

Net result: ~150 lines down from ~213.

### Modified: `api/src/app/db/repositories/block_repository.py`

Imports `ensure_block_uids` and `_extract_plain_text` from `app.utils.tiptap`.
Behavior identical. Module shrinks by ~40 lines.

### Modified: `api/src/app/services/note_processing_service.py`

Adds a single `_LOG.warning` when:

```
extraction_summary.relation_count == 0
AND extraction_summary.entity_count >= 3
AND distinct_blocks_with_at_least_one_concept >= 3
```

`distinct_blocks_with_at_least_one_concept` is computed inside
`derive_relations` during the single tree walk and threaded through
`NoteExtractionResult` — no second walk.

This catches future "the algorithm is silently failing" regressions on day one.
No alerting infrastructure beyond the log line.

## Purge list

| # | What | Reason |
|---|---|---|
| 1 | All `attrs.id` reads in `structure_relations.py` | Legacy attribute name; never set on real data. No fallback. |
| 2 | The `if not block_id: continue` gates | Unreachable post-contract; keeping them obscures the path. |
| 3 | `_walk_blocks`, `_list_item_groups`, `_bold_prefix_concepts` triple walk | Three walkers, three conventions, three ways to break. Replace with one. |
| 4 | Local `_text_of` in `structure_relations.py` | Duplicates `_extract_plain_text` in `block_repository.py`. Move to shared util. |
| 5 | All substring concept matching (`c.lower() in text.lower()`) | False-positive minefield. Replace with word-boundary regex. |
| 6 | All `attrs.id` fixtures in `tests/unit/test_structure_relations.py` | Match the dead format. Rewrite with `attrs.blockUid`. |
| 7 | Legacy AGE edge types: `CAUSES`, `IS_A`, `RELATED_TO`, `USES`, `BELONGS_TO`, `APPEARS_IN`, `PART_OF`, `CONTRASTS_WITH` | Emitted by the pre-refactor LLM pipeline. Concept-meta with no `source_note_id`, so per-note re-sync never removes them. One-shot Cypher purge. |
| 8 | `BlockInfo.block_id` field if unused after rewrite | Audit during implementation; if no consumer, delete. |
| 9 | `_ensure_block_uid` in `block_repository.py` (private) | Promote to `app/utils/tiptap.ensure_block_uids` (public). |

The deterministic pipeline still emits and preserves: `MENTIONS`, `CONTAINS`,
`HAS_CHILD`, `SUBTOPIC_OF`, `SYNONYM_OF`, plus the new structural relations
(`MENTIONED_TOGETHER`, `SIBLING_OF`, `REFERENCES`, `DEFINED_BY`).

## Testing

The bug went undetected because tests used the same wrong attribute as the
implementation. The testing strategy is re-grounded against real production
document shape.

### Production-shape fixture (the keystone test)

`tests/fixtures/notes/` — two real TipTap documents from the running database
(`note-1777849708116-379` "Syntax", `note-1777988937929-19` "2026 Goals"),
**pseudonymised** to remove personal content but preserving block structure
exactly. JSON files.

`tests/integration/test_structure_relations_against_production_shape.py` —
loads each fixture and asserts:

- `walk_structural_blocks` yields ≥N blocks all carrying non-empty `block_uid`
- `derive_relations(doc, concepts=[...])` produces ≥1 of each relation type
  the fixture's structure should yield (e.g., "Syntax" has nested headings →
  ≥1 SUBTOPIC_OF; "2026 Goals" has 8 bulletLists → ≥1 SIBLING_OF)
- No edge has empty `source` or `target`

This is the test that would have caught the original bug. Sub-100ms, no DB.

### Unit tests — rewritten in place

`tests/unit/test_structure_relations.py` — every fixture's `attrs.id` becomes
`attrs.blockUid`. Existing 6 cases preserved (5 relation types + walker). One
addition:

- `test_substring_match_does_not_produce_false_positives` — concepts `["AI", "JS"]`
  against block text `"again"` and `"adjustments"`. Pre-fix this would emit
  spurious MENTIONED_TOGETHER edges; post-fix produces none.

### New: `tests/unit/test_tiptap_utils.py`

- `ensure_block_uids` is idempotent (running twice produces identical UIDs)
- `ensure_block_uids` regenerates colliding UIDs
- `walk_structural_blocks` skips text/hardBreak/horizontalRule leaves but yields
  all 11 structural kinds
- `find_concept_mentions` matches `\bAI\b` but not `Again`; matches case-
  insensitive

### New: `tests/unit/test_document_contract.py`

- `TipTapBlockAttrs(blockUid=...)` validates; missing `blockUid` raises
  `ValidationError`
- A representative document round-trips through `ensure_block_uids` unchanged

### New: `tests/unit/test_note_processing_service_relations_warning.py`

Verify the warning fires when `relation_count == 0 AND entity_count >= 3 AND
blocks_with_concepts >= 3`. Uses `caplog`. Confirms it does NOT fire on
legitimately sparse notes.

### Coverage matrix

| Code change | Proves it works | Proves it doesn't recur |
|---|---|---|
| Read `blockUid` not `id` | rewritten `test_walk_blocks_extracts_block_ids_and_text` | production-shape fixture test |
| Drop missing-ID gate | (n/a — observed via fixture coverage) | production fixture; if upstream stamping breaks, zero edges |
| Word-boundary match | `test_find_concept_mentions_word_boundaries` | `test_substring_match_does_not_produce_false_positives` |
| Single tree walker | `test_tiptap_utils.test_walk_structural_blocks` | (refactor; no recurrence test needed) |
| Shared `ensure_block_uids` | `test_tiptap_utils` | existing `test_block_repository` UID-collision tests |
| Legacy AGE-edge purge | migration script logs counts | (one-shot data fix) |
| Contract pinned | `test_document_contract` | ValidationError on missing `blockUid` |
| Health metric | `test_note_processing_service_relations_warning` | log-line presence asserts behavior |

## Rollout & ordering

Seven commits, each leaving the test suite green:

1. Add `app/utils/tiptap.py` + `tests/unit/test_tiptap_utils.py`. Nothing
   imports it yet.
2. Add shared contracts (`document.py` + `document.ts`) +
   `tests/unit/test_document_contract.py`. Nothing imports them yet.
3. Migrate `block_repository.py` to import from `app.utils.tiptap`.
   `test_block_repository.py` updated to import from new location.
4. Rewrite `structure_relations.py` around the shared util. Rewrite
   `test_structure_relations.py` with `blockUid` fixtures + the false-positive
   regression test.
5. Add production-shape fixture +
   `tests/integration/test_structure_relations_against_production_shape.py`.
6. Add the `relation_count == 0` warning + its test.
7. Add `api/src/app/scripts/purge_legacy_relations.py`.

### Backfill — two distinct migrations

**(a) Re-derive structural relations for all existing notes.** Use the
existing `api/src/app/scripts/reextract_all_notes.py`. Per-note delete-and-
replace sync recreates the new relation types.

**(b) Purge legacy LLM-era edges.** New script
`api/src/app/scripts/purge_legacy_relations.py` iterates
`public.users.schema_name`, runs per tenant graph (`nn_<schema>`):

```cypher
MATCH ()-[r]->()
WHERE type(r) IN [
  'CAUSES', 'IS_A', 'RELATED_TO', 'USES',
  'BELONGS_TO', 'APPEARS_IN', 'PART_OF', 'CONTRASTS_WITH'
]
DELETE r
RETURN type(r) AS rel, count(*) AS n
```

Logs `(rel, count)` per tenant + totals. Idempotent.

### Deploy order

1. Deploy code (steps 1–7).
2. **Backup**: `pg_dump` the AGE graph schemas before the destructive purge.
   `infra/backups/age-graph-pre-purge-2026-05-09.sql`.
3. **Pre-purge tally**: run a per-tenant Cypher count of the legacy edge types
   (same `WHERE type(r) IN [...]` clause as the purge) and write the totals
   to a transient `infra/backups/age-graph-pre-purge-counts.txt` for
   comparison.
4. Run `purge_legacy_relations.py`. Confirm its reported deletion counts
   match the pre-purge tally exactly.
5. Run `reextract_all_notes.py`. Confirm `relation_count > 0` in the
   resulting `extraction_summary` rows.
6. Spot-check the AGE graph: edge-type tallies should be `MENTIONS, CONTAINS,
   HAS_CHILD, MENTIONED_TOGETHER, SUBTOPIC_OF, SYNONYM_OF, SIBLING_OF,
   REFERENCES, DEFINED_BY` and **nothing else**.

Both backfill scripts are operator-run, not Alembic — they're data migrations
on a property graph, not schema migrations.

### Rollback

- **Code**: revert the seven commits. Editor and notes API unaffected.
- **Backfill (a)**: not reversible in the literal sense, but per-note
  delete-and-replace sync makes the next save the cleanup.
- **Backfill (b)**: irreversible without the LLM-era pipeline (which is
  deleted). The `pg_dump` backup is the safety net.

### Observability

- Day 0: tail logs for the new `relation_count == 0` warning. A spike means a
  new bug.
- Day 1–7: spot-check that newly-saved notes produce non-trivial
  `extraction_summary`.
